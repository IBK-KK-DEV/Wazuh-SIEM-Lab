# Wazuh-SIEM-Lab
# Wazuh HIDS Home Lab — Kali Linux + Windows 11

A fully documented Host-based Intrusion Detection System (HIDS) lab built with **Wazuh 4.14.5**, featuring a Kali Linux manager/indexer/dashboard stack and a Windows 11 Pro agent, connected over a bridged home network using Oracle VirtualBox.

## Features Demonstrated

### Detection Rules (custom local_rules.xml)

| Rule ID | Description | Trigger | Level |
|---------|-------------|---------|-------|
| 100001 | Windows failed logon | Event ID 4625 | 6 |
| 100002 | Brute force detection | 5+ failures/60s from same IP | 12 |
| 100003 | File modification via FIM | Syscheck rule 550 | 8 |
| 100004 | Removable storage connected | Event ID 2003 | 7 |
| 100005 | SSH brute force | 5+ SSH failures/60s | 12 |

### Active Response
- **firewall-drop** — auto-blocks attacker IP via `iptables` on brute force detection
- **180-second timeout** — automatic unblock after cooldown period
- **netsh** — Windows-side block via agent (configured, agent-side)

### File Integrity Monitoring (FIM)
- Real-time monitoring of `C:\WazuhTest` directory
- Cryptographic hash tracking (MD5/SHA1/SHA256)
- Before/after diff with size, mtime, permission ACL capture
- Content change tracking (`report_changes="yes"`)

### Windows Audit Policies Enabled
- Logon / Logoff (4624, 4625, 4634)
- Credential Validation (4776)
- Object Access / File System (4663) — *see known limitations*
- Audit Policy Change (4719)
- Process Creation (4688)
- Removable Storage (6416)

### Compliance Mappings (auto-detected)
- PCI DSS 10.2.4, 10.2.5, 10.2.7, 11.4
- GDPR IV 35.7.d, IV 32.2
- HIPAA 164.312.b, 164.312.c.1
- NIST 800-53 AU.6, AU.14, AC.7, SI.7

## Quick Setup

### 1. Kali — Add Wazuh Repo & Install

```bash
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | sudo gpg --dearmor -o /usr/share/keyrings/wazuh.gpg
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | sudo tee /etc/apt/sources.list.d/wazuh.list
sudo apt update
sudo apt install wazuh-manager wazuh-indexer wazuh-dashboard -y
```

### 2. Kali — Generate Certificates

```bash
curl -sO https://packages.wazuh.com/4.14/wazuh-certs-tool.sh
# Edit config.yml with your node IPs, then:
sudo bash wazuh-certs-tool.sh -A
```

### 3. Kali — Deploy Certs & Start Services

```bash
# Copy certs to indexer and dashboard directories
sudo systemctl enable wazuh-indexer wazuh-manager wazuh-dashboard
sudo systemctl start wazuh-indexer wazuh-manager wazuh-dashboard
sudo /usr/share/wazuh-indexer/bin/indexer-security-init.sh
```

### 4. Kali — Install Filebeat (Wazuh OSS build)

```bash
curl -sO https://packages.wazuh.com/4.x/apt/pool/main/f/filebeat/filebeat-oss-7.10.2-amd64.deb
sudo dpkg -i filebeat-oss-7.10.2-amd64.deb
sudo curl -so /etc/filebeat/filebeat.yml https://packages.wazuh.com/4.14/tpl/wazuh/filebeat/filebeat.yml
# Set credentials, then:
sudo systemctl start filebeat
```

### 5. Windows — Install Agent (CMD as Admin)

```cmd
curl -o "%TEMP%\wazuh-agent.msi" "https://packages.wazuh.com/4.x/windows/wazuh-agent-4.14.5-1.msi"
msiexec /i "%TEMP%\wazuh-agent.msi" /q WAZUH_MANAGER="<KALI_IP>"
net start WazuhSvc
```

### 6. Access Dashboard

```
https://<KALI_IP>
Username: admin
Password: <generated by wazuh-passwords-tool.sh>
```

## Custom Detection Rules

```xml
<group name="custom_windows_hids,">

  <!-- Rule 1: Windows failed logon (Event ID 4625) -->
  <rule id="100001" level="6">
    <if_sid>60103</if_sid>
    <field name="win.system.eventID">^4625$</field>
    <description>Custom: Windows failed logon attempt (Event 4625)</description>
    <group>authentication_failed,pci_dss_10.2.4,</group>
  </rule>

  <!-- Rule 2: Brute force - 5 logon failures in 60 seconds -->
  <rule id="100002" level="12" frequency="5" timeframe="60">
    <if_matched_sid>100001</if_matched_sid>
    <same_source_ip />
    <description>Custom: Windows Brute Force - 5+ failures in 60s</description>
    <group>authentication_failures,pci_dss_10.2.4,gdpr_IV_35.7.d,</group>
  </rule>

  <!-- Rule 3: File modification via FIM (replaces 4663 eventchannel) -->
  <rule id="100003" level="8">
    <if_sid>550</if_sid>
    <description>Custom: Sensitive file modification detected via FIM (WazuhTest)</description>
    <group>file_access,pci_dss_10.2.7,syscheck,</group>
  </rule>

  <!-- Rule 4: USB / Removable storage connected -->
  <rule id="100004" level="7">
    <if_sid>60000</if_sid>
    <field name="win.system.eventID">^2003$</field>
    <description>Custom: Removable storage device connected</description>
    <group>removable_storage,</group>
  </rule>

  <!-- Rule 5: SSH Brute Force - Active Response trigger -->
  <rule id="100005" level="12" frequency="5" timeframe="60">
    <if_matched_sid>5712</if_matched_sid>
    <same_source_ip />
    <description>Custom: SSH Brute Force detected - triggering Active Response</description>
    <group>authentication_failures,</group>
  </rule>

</group>
```

## Active Response Configuration

```xml
<!-- Block attacker on Kali using iptables -->
<active-response>
  <disabled>no</disabled>
  <command>firewall-drop</command>
  <location>local</location>
  <rules_id>100002,100005</rules_id>
  <timeout>180</timeout>
</active-response>

<!-- Block attacker on Windows agent using netsh -->
<active-response>
  <disabled>no</disabled>
  <command>netsh</command>
  <location>defined-agent</location>
  <agent_id>001</agent_id>
  <rules_id>100002,100005</rules_id>
</active-response>
```

**Verification:**
```bash
# After brute force attack, confirm IP blocked
sudo iptables -L INPUT -n | grep <ATTACKER_IP>
# Output: DROP  all  --  <ATTACKER_IP>  0.0.0.0/0
```

## Known Limitations & Findings

### Windows Event ID 4663 (Object Access) — Eventchannel Limitation

During testing, **Event ID 4663 (File System Object Access)** was confirmed to NOT forward to the Wazuh manager via the Windows eventchannel subscription, despite all prerequisites being met:

- ✅ SACL applied and verified (`Get-Acl -Audit`)
- ✅ Object Access / File System auditing enabled (`auditpol`)
- ✅ 4663 generating locally (`Get-WinEvent` confirmed)
- ✅ Wazuh agent Security channel subscription active (no errors)
- ✅ Other Security channel events (4625, 4624, 4719, 6416) forwarding successfully

**Root cause:** Known Wazuh Windows agent limitation with high-volume object-access audit events (4663/4656/4658) via the EvtSubscribe eventchannel pipeline.

**Workaround implemented:** Rule 100003 repurposed to use Wazuh's native FIM/syscheck engine (`<if_sid>550</if_sid>`), which provides superior detection with cryptographic hash verification and real-time change tracking.

### Windows Security Channel Subscription Drop

The Wazuh agent's Security channel eventchannel subscription silently drops after certain Windows service restart sequences. 

**Fix:**
```powershell
net stop WazuhSvc
Stop-Service EventLog -Force
Start-Sleep -Seconds 3
Start-Service EventLog
Start-Sleep -Seconds 5
net start WazuhSvc
```

**Permanent fix:** Scheduled task to restart WazuhSvc at system startup.

## Adding Additional Agents

### Linux (Ubuntu/Debian)

```bash
# Add Wazuh repo
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | sudo gpg --dearmor -o /usr/share/keyrings/wazuh.gpg
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | sudo tee /etc/apt/sources.list.d/wazuh.list
sudo apt update

# Install agent pointing to Kali manager
sudo WAZUH_MANAGER="192.168.18.136" apt install wazuh-agent -y

# Start
sudo systemctl enable wazuh-agent
sudo systemctl start wazuh-agent
```

### Windows (additional machine)

```cmd
curl -o "%TEMP%\wazuh-agent.msi" "https://packages.wazuh.com/4.x/windows/wazuh-agent-4.14.5-1.msi"
msiexec /i "%TEMP%\wazuh-agent.msi" /q WAZUH_MANAGER="192.168.18.136"
```

### macOS

```bash

uname -m

# Apple Silicon
curl -so wazuh-agent.pkg https://packages.wazuh.com/4.x/macos/wazuh-agent-4.14.5-1.arm64.pkg

# curl -so wazuh-agent.pkg https://packages.wazuh.com/4.x/macos/wazuh-agent-4.14.5-1.intel64.pkg

# Start agent
sudo /Library/Ossec/bin/wazuh-control start

# Verify
sudo /Library/Ossec/bin/wazuh-control status
```

```bash
sudo /var/ossec/bin/agent_control -l
```

```

ID: 001, Name: ibk170, IP: any, Active
```

No manager restart required — Wazuh auto-accepts new agents.  
New agents appear in **Wazuh Dashboard → Endpoints** within ~60 seconds.
